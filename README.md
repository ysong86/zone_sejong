# 세종 생활권 재구조화 상황판

행복도시 6개 생활권 체계가 지금의 도시기능과 앞으로의 국가계획·세종시 계획을
담고 있는지 지표와 지도로 점검하는 정적 상황판입니다. `dashboard.html` 한 파일로
열립니다.

```
C:\Python313\python.exe run.py            샘플로 생성
C:\Python313\python.exe run.py --open     생성 후 열기
C:\Python313\python.exe run.py --probe    포털 API 상태(403 = 활용신청만 남음)
C:\Python313\python.exe run.py --collect  승인된 API 원 응답을 data/raw 에 저장
C:\Python313\python.exe run.py --live     data/latest.json 실측을 반영해 생성
```

## 세 검토축

| 축 | 질문 | 대표 지표 |
|---|---|---|
| A 기능 재정립 | 생활권마다 계획된 기능이 실제로 형성됐나 | 직주비, 기능혼합도, 상가 공실, 계획기능 특화도(LQ) |
| B 생활권 간 연계 | 생활권이 서로 기능을 주고받나 | 15분 생활서비스, 정류장 400m, BRT 도보, 생활권 간 통행 |
| C 국가중추·광역 | 국가중추기능·대전·청주와의 관계가 생활권 위계에 들어 있나 | 시외 통근, 공공·연구 종사자, 아파트 가격 |

## 파일

- `livingzone.py` — 생활권 정의, 동별 샘플 지표, 지표 정의, 거점, 흐름, 이론·문헌, 개선방향, 자료원. **내용을 고치려면 여기만 고치면 됩니다.**
- `template.html` — 화면(지도·차트 모두 바닐라 JS + SVG)
- `build_dashboard.py` — 데이터를 템플릿에 넣어 한 파일로
- `collect.py` — API 타진·원 응답 저장
- `tools/make_zones.py` — 경계 정리·생활권 합집합(shapely, 한 번만)
- `assets/` — `sejong_admin.json`·`sejong_roads.json` 은 교통 상황판에서 복사

## 알아둘 것

- **실측 지표 14개**(2026-09-24 연동, 공원·도서관·체육 포함): 인구·증감·세대당 인구·60세 이상·0~19세(행안부 주민등록),
  기능혼합도·1천 명당 점포·15분 생활서비스(상가정보 + 심평원 병원), 정류장 400m·BRT 도보(TAGO),
  ㎡당 아파트가(실거래 12개월 중앙값), 1만 명당 의사(심평원). 나머지 6개와 생활권 특화도·통행은 **샘플**.
- 인증키는 `config.json` 의 `portal_key`(저장소에 안 올라감). 갱신:
  `run.py --collect --live` → dashboard.html 을 gh-pages 의 index.html 로 덮어쓰기.
- **지도 단위는 행정동 25곳**(도담·어진동 합침). 법정동 면을 `livingzone.ADMIN` 대로 합친다.
  집현동 행정동은 4생활권(집현)과 5생활권(합강·다솜·용호)을 함께 관할해 5생활권 통계를 따로 뗄 수 없다.
- 연령 통계가 10세 단위라 65세가 아니라 **60세 이상**, 유소년은 **0~19세**로 잡았다.
- 점포 자료의 행정동명은 분동 전(집현동 없음)이라, 점포·정류장·병원은 **좌표로** 행정동 면에 넣는다.
- 거주 위치 대용: 행정동 면 안 120m 격자 중 점포·정류장 300m 안의 점(시가지 격자점).
  15분 서비스는 직선 1km(우회 1.25배 ≈ 도보 15분), BRT 정류장은 BRT 도로선 40m 안 정류장.
  읍면은 BRT 순환축 밖이라 BRT 도보를 계산하지 않는다.
- 1년 증감은 분동 전과 비교해야 해서 반곡·집현을 한 묶음으로 계산한다(`CHG_GROUPS`).
- OSM 에 **어진동·가람동 경계가 없습니다**. 나성동·세종동 면은 `make_zones.py` 가 겹침을 빼서 정리합니다.
